## 3. 核心架构缺陷：没有“方案”实体

系统有三套事实源，互不同步：

| 事实源 | 内容 | 生命周期 |
|---|---|---|
| SQLite `files` | 文件元数据 | 持久 |
| 内存 `BigTrip/SubTrip` | 每次 preview/execute 重算 | 请求级 |
| 前端 localStorage | 重命名、容器、合并 | 本机浏览器 |

`/api/archive/execute` 的**结构相关参数**只接收：

- `trip_overrides`（按原始文件夹名的重命名）
- `containers`（容器名 → 原始子行程文件夹）
- `archive_mode`

它**不接收合并后的树，也不接收文件到子行程的归属**，而是重新跑 `segment_into_trips`。

### 3.1 这会导致什么

- 重命名：生效（靠文件夹名覆盖）。
- 容器：基本生效（靠原始文件夹名映射），但前端合并/下标变化后会错位。
- **大行程合并：不生效**（见 3.2）。
- 刷新/换机器：本地编辑丢失；源目录变化后，旧树静默失效。
- 归档结果可能与用户确认的方案不一致，且没有冲突提示。

### 3.2 大行程合并：一个被“前端方案”掩盖的缺陷

你 2026-07-02 提出：朋友传来的照片没有 GPS/时间，被单独归成“待分类”大行程，希望并入主行程。

Cline 里 agent 的方案原话是：

> “方案一：……将其所有子行程全部迁移合并进目标大行程……**完全不需要改后端 archive 逻辑**。”
> “缺点：合并后‘待分类’大行程的文件夹命名会被纳入主行程的时间范围重算。”

这个假设是错的：**execute 从数据库重算，不会收到前端的合并结果**；源大行程的文件时间没有变化，重算后仍然会单独成组。除非时间差恰好 ≤30 天，否则合并只存在于前端。

结论：大行程合并是**按“前端-only”设计的功能**，与执行端模型不匹配。项目把它列为“已完成”，但没有证据表明它经过归档落盘验证。

### 3.3 子行程合并：已取消，但留下死代码

你 2026-07-01 明确说：

> “之前不是说取消子行程合并操作吗，改为行程重建，这样就不会存在合并后无法拆分的问题吗？”

核对代码：

这不是 P0 功能缺陷，而是需要清理的死代码与文案。

## 5. 安全与合规

1. **凭据**：旧 Key 在公开历史中，按已泄露处理；先轮换，再清历史，再开 Secret Scanning。
2. **本地 API 无鉴权 + CORS `*`**：任意网页可调用 `scan/clear`、`archive/cleanup`、`archive/execute`。
3. **任意文件读取**：`/api/media/thumbnail?path=` 接受任意绝对路径。
4. **路径穿越写入**：`display_name` 可含 `..\` 或绝对路径（M3.2b 已修：统一净化 + 后端校验）。
5. **Electron `webSecurity: false`** + 地图 iframe 同源，XSS 可触达 `electronAPI`。
6. **隐私**：GPS 会发往高德，地图瓦片请求 CartoDB/OSM；应在 UI 明示并提供纯离线模式。

- `plan_trips`：`id, plan_id, parent_id, kind(big/sub), folder_name, display_name, start_date, end_date, sequence_num, location_label, container_name, sort_order`
- `plan_files`：`id, plan_id, trip_id, media_file_id, target_rel_path, status, error`

### 12.2 接口

- `POST /api/archive/plans`：生成方案
- `GET /api/archive/plans/{id}`：读取完整树 + 文件
- `PATCH /api/archive/plans/{id}`：重命名 / 合并 / 容器 / 模式（拆分未实现）
- `POST /api/archive/plans/{id}/execute`：只消费方案，不重算
- `DELETE /api/archive/plans/{id}`：放弃草稿（未实现）
- `preview`：已标记 deprecated，保留为旧会话回退

### 12.3 规则

- 执行前校验 `source_snapshot`，不一致 409。
- `plan_version` 乐观锁。
- 执行幂等、只重试失败项：**尚未实现**（当前失败项需重新生成方案）。
- 方案废弃保留审计记录：**尚未实现**（`DELETE` 未做）。

### 12.4 前端

- `appStore` 只保留 `currentPlanId`。
- ScanPage / ArchivePage / TripRebuilderPage 读写同一 plan。
- 编辑走 PATCH；失败回滚 UI。
- 重启后从 plan 恢复：**尚未实现**（`planId/planVersion` 目前仅运行时保存）。

### 12.5 验收

- 合并两个子行程 → 磁盘只有一个目录。
- 大行程合并 → 源大行程消失，文件进入目标目录。
- 重命名 → 重启后仍生效。
- 容器 → `big/container/sub/file`。
- 源目录变化 → 执行被拒绝并提示。
