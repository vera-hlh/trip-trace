# Phase 1：景区字段与候选（实现记录）

**日期**：2026-11-18  
**范围**：地理编码阶段产出景区候选、文件级景区字段、POI 审核页显示与手动修正。  
**不包含**：按景区自动切分、拆分 UI、别名表、LLM。

---

## 1. 已实现

### 1.1 数据字段

`files` / `geocode_cache` 新增：

```text
area_name            # 景区/片区，如 三峡大坝旅游区
area_source          # amap_aoi | amap_parent | amap_nearby | manual
area_confidence      # 0-1
area_candidates_json # 候选列表（名称/类型/距离/来源）
```

字段迁移已加入 `_run_migrations()`，旧库自动补列。

### 1.2 高德候选

`reverse_geocode_gaode` 改为：

1. `regeo?extensions=all` 获取 AOI；
2. AOI 优先选 `type=110202` / 名称含“景区/旅游区/度假区/风景区”；
3. AOI 本身可能是子景区（如坛子岭），继续用 `place/detail` 的 `parent` 链向上；
4. 无 AOI 时，用 `place/around` 最佳 POI 的 `parent` 链向上；
5. 父级链取最高层景区/国家级景点；
6. 最后兜底：POI 本身是“国家级景点/景区/旅游区”。

候选写入 `GeoLocation.area_*`，并随 `geocode_cache` 持久化。

### 1.3 手动修正

新增：

```http
PUT /api/scan/area-group
{
  "province": "湖北省",
  "city": "宜昌市",
  "old_area": "坛子岭风景区",
  "old_poi": "坛子岭",
  "new_area": "三峡大坝旅游区"
}
```

- 只更新当前匹配组文件；
- 写入 `area_source=manual`、`area_confidence=1.0`；
- **不写 geocode_cache、不建全局别名**；
- 避免一次活动/修正污染以后数据。

### 1.4 前端

POI 审核行新增：

- 景区标签：`🏞 三峡大坝旅游区`；
- 展开后可编辑景区名并保存；
- 显示来源（amap_aoi/amap_parent/manual）；
- 候选景区按钮（AOI/父级/距离），点击填入编辑框；
- 多选 POI 组后批量设置同一景区；
- 已有景区名通过 datalist 提供复用建议；
- 保留原有 POI 编辑与候选。

### 1.5 后续交互修正

- 批量设置景区后清空输入框；
- POI 组缩略图超过 6 张时显示“加载更多”，按 `GET /api/scan/poi-files` 分页读取全部文件；
- 缩略图增加勾选框，可只修改选中照片的 POI：
  - `PUT /api/scan/photo-poi`
  - 只更新选中路径，`geocode_source=manual`，不影响同组其他照片；
- 刷新 POI 分组后写入操作日志，提示成功/失败和组数；
- 批量景区设置仍按组逐次请求，组数很多时请求偏多。

## 3. 已知不足

- 部分城区/道路坐标 `area_name` 为空（预期，需人工或后续规则）；
- 同一景区可能出现变体名（如“清江画廊旅游度假区”“清江画廊风景区”），目前只能手动复用/修正，尚未自动归一化；
- 批量设置按组顺序调用接口，组数很多时请求数偏多；
- 尚未按景区自动切分，也未做拆分 UI；
- 未引入 LLM。
