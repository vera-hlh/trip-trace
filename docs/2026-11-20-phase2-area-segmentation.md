# Phase 2：景区边界参与自动切分（实现记录）

**日期**：2026-11-20  
**范围**：`MediaItem.area_name`、`SubTrip.area_name`、`PlanTrip.area_name`；景区变化自动切分子行程。  
**不包含**：手动拆分 UI、景区名归一化、LLM。

---

## 1. 实现

### 1.1 数据结构

- `MediaItem.area_name`；
- `SubTrip.area_name`；
- `PlanTrip.area_name`（SQLite 自动迁移）；
- 生成方案时，`location_key` 追加景区：
  ```text
  CN/湖北省/宜昌市/三峡大坝旅游区
  ```

### 1.2 切分规则

在原有规则前增加：

```text
景区变化 → 强制新子行程（即使时间差很短）
```

- 同一景区 → 继续按原时间/地点规则；
- 无景区 → 回退城市 + 时间；
- 子行程名称优先使用景区名；
- `infer_location_for_gps_less` 同时传播 `area_name`。

### 1.3 方案输出

`GET /api/archive/plans/{id}` 的子行程新增：

```json
{
  "folder": "11_听风谷_0213",
  "area_name": "听风谷",
  "location": "听风谷",
  "file_count": 22
}
```

前端 `PlanTripNode` / `SubTripData` 增加 `areaName`。

---

## 2. 真实宜昌样本验证

样本：`2026年2月07日-13日 衡山、醴陵、宜昌`  
302 个媒体文件，301 个有 GPS。

| 项目 | 结果 |
|---|---|
| 扫描 | 302 |
| 地理编码 | 301 |
| 错误 | 0 |
| 高德调用 | 27 |
| 大行程 | 1 |
| 子行程 | 13 |
| 文件 | 302 |

关键子行程：

| 子行程 | 文件数 |
|---|---:|
| 南岳衡山风景名胜区 | 5 + 67 |
| 南岳里庙会文化美食街区 | 7 |
| 株洲伽蓝庙 | 14 |
| 松山湖旅游度假区宜昌展厅 | 3 |
| 坛子岭风景区 | 5 |
| 三峡大坝旅游区 | 1 |
| 清江画廊旅游度假区 | 60 |
| 听风谷 | 22 |
| 三峡人家风景区 | 98 |
| 湖南烈士公园 | 1 |

结论：

- 听风谷已独立为 22 张；
- 三峡人家 98 张；
- 清江画廊 60 张；
- 景区边界确实参与了切分，行程不再把三个宜昌景区合成一个。

---

## 3. 已知问题

- 坛子岭风景区（5）和三峡大坝旅游区（1）仍被拆成两个子行程，需要后续景区名归一化或人工合并；
- 松山湖旅游度假区宜昌展厅（3）是 API 返回结果，暂保留；
- 部分城区/道路 area 为空（如宜昌基督教堂 16 张），仍按地点/时间切分；
- 还没有手动拆分 UI；
- 没有景区别名表/相似名合并；
- 没有 LLM。
