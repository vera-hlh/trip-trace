# Phase 2：景区边界参与自动切分（实现记录）

**日期**：2026-11-20  
**范围**：`MediaItem.area_name`、`SubTrip.area_name`、`PlanTrip.area_name`；景区变化自动切分子行程；手动拆分 API/UI。  
**不包含**：景区名归一化、LLM。

---

## 1. 实现

### 1.1 数据结构

- `MediaItem.area_name`；
- `SubTrip.area_name`；
- `PlanTrip.area_name`（SQLite 自动迁移）；
- 生成方案时，`location_key` 追加景区：
  ```text
  CN/湖北省/宜昌市/三峡大坝旅游区
  ```

### 1.2 切分规则

在原有规则前增加：

```text
景区变化 → 强制新子行程（即使时间差很短）
```

- 同一景区 → 继续按原时间/地点规则；
- 无景区 → 回退城市 + 时间；
- 子行程名称优先使用景区名；
- `infer_location_for_gps_less` 同时传播 `area_name`。

### 1.3 方案输出

`GET /api/archive/plans/{id}` 的子行程新增：

```json
{
  "folder": "11_听风谷_0213",
  "area_name": "听风谷",
  "location": "听风谷",
  "file_count": 22
}
```

前端 `PlanTripNode` / `SubTripData` 增加 `areaName`。

## 2. 真实宜昌样本验证

样本：`2026年2月07日-13日 衡山、醴陵、宜昌`  
302 个媒体文件，301 个有 GPS。

| 项目 | 结果 |
|---|---|
| 扫描 | 302 |
| 地理编码 | 301 |
| 错误 | 0 |
| 高德调用 | 27 |
| 大行程 | 1 |
| 子行程 | 13 |
| 文件 | 302 |

关键子行程：

| 子行程 | 文件数 |
|---|---:|
| 南岳衡山风景名胜区 | 5 + 67 |
| 南岳里庙会文化美食街区 | 7 |
| 株洲伽蓝庙 | 14 |
| 松山湖旅游度假区宜昌展厅 | 3 |
| 坛子岭风景区 | 5 |
| 三峡大坝旅游区 | 1 |
| 清江画廊旅游度假区 | 60 |
| 听风谷 | 22 |
| 三峡人家风景区 | 98 |

结论：

- 听风谷已独立为 22 张；
- 三峡人家 98 张；
- 清江画廊 60 张；
- 景区边界确实参与了切分，行程不再把三个宜昌景区合成一个。

## 3. 手动拆分（Phase 2b）

接口：

```http
PATCH /api/archive/plans/{id}
{
  "plan_version": 2,
  "splits": [{
    "trip_id": 12,
    "groups": [
      { "name": "三峡大坝", "file_ids": [1, 2, 3] },
      { "name": "三峡人家", "file_ids": [4, 5, 6] }
    ]
  }]
}
```

规则：

- 只能拆 `kind=sub`；
- 只能 draft 方案；
- 每个分组必须非空、文件不重复；
- 必须覆盖原子行程全部文件；
- 拆分后重算目标路径、重新排序、方案版本 +1；
- 组名走 Windows 目录名校验。

前端：

- 行程树子行程行新增「✂️ 拆分」；
- 弹窗列出全部照片（名称/时间/景区/POI）；
- 勾选要拆出的照片；
- 输入新子行程名称；
- 剩余照片保留原名称；
- 可重复拆分，把一个大子行程拆成多个。

## 4. 景区名归一化/别名（Phase 2c）

数据结构：

```text
area_aliases
  id
  city
  alias_name
  canonical_name
  created_at
  UNIQUE(city, alias_name)
```

接口：

```http
PUT /api/scan/area-merge
{
  "city": "宜昌市",
  "source_names": ["坛子岭风景区", "三峡大坝景区"],
  "canonical_name": "三峡大坝旅游区",
  "apply_existing": true
}
```

规则：

- 别名按城市生效，避免跨城市串名；
- `apply_existing=true` 时更新当前城市已扫描文件；
- 以后地理编码遇到这些变体名，会解析为规范名；
- 别名跟随最多 5 层，防止环；
- 不会自动删除历史文件，仍以当前文件为准。

前端：

- POI 审核右上角新增「🔗 景区归一化」；
- 选择城市；
- 勾选要归一的变体名；
- 输入或选择规范名；
- 执行后刷新 POI 分组；
- 示例：`坛子岭风景区 → 三峡大坝旅游区`。

> 归一化后，已有方案不会自动重算；需要重新生成方案。

## 5. 已知问题

- 坛子岭风景区/三峡大坝旅游区 可通过「景区归一化」建立别名；已有方案需重新生成；
- 松山湖旅游度假区宜昌展厅（3）是 API 返回结果，暂保留；
- 部分城区/道路 area 为空（如宜昌基督教堂 16 张），仍按地点/时间切分；
- 拆分按“选中/剩余”两组合并，暂不支持一次拆成 3 组以上（可重复拆分）；
- 尚未做别名的删除/编辑列表 UI（只有接口与合并入口）；
- 没有 LLM。
