# 高德 AOI / 父级 POI 实验记录（宜昌）

**日期**：2026-11-16  
**样本**：`2026年2月07日-13日 衡山、醴陵、宜昌`（302 张 JPG，301 张有 GPS）  
**目的**：验证高德能否在“地理编码/POI 审核”阶段给出景区级候选，而不是等拆分时人工判断。

---

## 1. 结论速览

- `regeo?extensions=all` 的 `aois` **能返回部分景区**（如“三峡大坝旅游区”“三峡人家风景区”）；
- AOI 覆盖率不够：宜昌 19 个坐标簇中只有 **7 个**返回 AOI，其中 5 个是景区，2 个是商场/酒店；
- **`place/around` 返回的 POI 带 `parent` 字段**，用 `place/detail` 可以沿父级链找到景区：
  - `倒影峡` → `清江画廊旅游度假区`
  - `185园区-观景台` → `坛子岭风景区` → `三峡大坝旅游区`
  - `悬棺` → `三峡人家风景区`
- 因此建议采用 **AOI + 父级链** 双通道，而不是只依赖 AOI 或 POI 名称：
  - AOI 优先；
  - 没有 AOI 时，用周边 POI 的 `parent` 链找父级景区；
  - 仍不确定时给候选让用户确认，LLM 只做歧义辅助。

---

## 2. 实验数据

### 2.1 坐标簇

301 张 GPS 照片按经纬度 0.01° 聚合，宜昌范围共 **19 个簇**。

### 2.2 AOI 覆盖

| 类型 | 簇数 | 照片数 | 例子 |
|---|---:|---:|---|
| 景区 AOI | 5 | 88 | 三峡大坝旅游区、三峡人家风景区 |
| 非景区 AOI | 2 | 18 | 时代购物广场、酒店 |
| 无 AOI | 12 | — | 清江画廊、部分三峡人家、城区 |

典型：

- `30.83,111.01` → AOI `三峡大坝旅游区`（type `110202`，距离 47m）
- `30.80,111.16` → AOI `三峡人家风景区`（type `110202`，距离 0m）
- `30.46,111.12`（清江画廊）→ **无 AOI**

### 2.3 父级 POI 链

对无 AOI 的 12 个簇，调用 `place/around?types=风景名胜&radius=5000`，再对每个 POI 的 `parent` 调 `place/detail`：

| 坐标簇 | 照片数 | 周边 POI 示例 | 父级链结果 |
|---|---:|---|---|
| 30.45,111.14 | 5 | 仙人寨 | 清江画廊旅游度假区 |
| 30.46,111.11 | 4 | 倒影峡 | 清江画廊旅游度假区 |
| 30.46,111.12 | 25 | 倒影峡 | 清江画廊旅游度假区 |
| 30.46,111.13 | 19 | 骆驼饮水 | 清江画廊旅游度假区 |
| 30.46,111.14 | 3 | 鼓乐堂 | 清江画廊旅游度假区 |
| 30.47,111.12 | 3 | 长阳珍稀蝴蝶模式产地纪念馆 | 部分该纪念馆，部分清江画廊 |
| 30.47,111.13 | 1 | 清江画廊旅游度假区 | 清江画廊旅游度假区 |
| 30.69,111.28 | 3 | 磨基山森林公园观景台 | 磨基山森林公园（城市公园） |
| 30.78,111.16 | 5 | 胡金滩码头 | 三峡人家风景区 |
| 30.80,111.15 | 10 | 悬棺 | 三峡人家风景区 |
| 30.80,111.22 | 22 | 听风谷观景台 | 听风谷（独立景点，需人工确认是否归入三峡人家） |

结论：

- **清江画廊 60 张左右全部可以通过父级链归到“清江画廊旅游度假区”**，不需要 LLM；
- 三峡人家缺 AOI 的簇也能通过父级链归到“三峡人家风景区”；
- `听风谷` 这种独立景点需要人工判断，属于 LLM/人工候选的典型场景；
- 城市公园（磨基山）可以被识别，但不一定是用户想要的“景区”，需要审核。

## 3. 推荐架构

### 3.1 景区确定时机

在地理编码/POI 审核阶段完成，不等到拆分：

```text
扫描
  → 地理编码
      → 城市/区县
      → 具体 POI
      → 景区候选（AOI / 父级链 / 周边 POI）
  → 景区审核（批量确认/修改）
  → 自动切分（城市 + 景区 + 时间）
  → 行程树（拆分只做结构调整）
  → 归档
```

### 3.2 候选优先级

1. **AOI**：`regeo?extensions=all` 的 `aois`，type `110202` 或名称含“景区/旅游区/度假区”；
2. **父级 POI 链**：周边 `place/around` POI 的 `parent` → `place/detail`，向上最多 3 层；
3. **周边 POI 本身**：没有父级时，取最近的 `风景名胜;风景名胜;国家级景点`；
4. **人工/别名**：用户确认后写本地别名，例如 `听风谷 → 三峡人家`；
5. **LLM**：仅对候选歧义做选择，不凭空造景区。

### 3.3 数据字段

```text
files.area_name           # 景区/片区
files.area_source         # amap_aoi / amap_parent / amap_nearby / alias / manual / llm
files.area_confidence     # 可选
geocode_cache.*           # 同样的缓存字段
plan_trips.area_name      # 子行程内文件一致时派生
```

源头仍是文件/POI 组；子行程景区名是派生结果。

### 3.4 缓存

- `geocode_cache` 增加 `area_name/area_source/area_candidates_json`；
- `place/detail` 按 POI ID 缓存，避免重复查父级；
- 同一坐标网格只查一次；
- 空结果也要缓存（带 TTL），避免反复请求。

## 5. LLM 的定位

适合：

- 多个父级候选时选择，如“听风谷”是否归入“三峡人家”；
- 同一景区的不同名称合并（三峡大坝 / 三峡大坝旅游区 / 三峡水利枢纽）；
- 城市公园是否应作为景区。

不适合：

- 没有候选时凭空猜景区；
- 覆盖用户手动修改；
- 直接写库不审核。

建议：

- v1.0 先做 AOI + 父级链 + 人工确认；
- 收集真实歧义样本后，再决定是否接 LLM；
- 如接，优先本地模型/用户自带 Key，输入只给城市、POI、候选列表，输出限制在候选或 `unknown`。

---

## 6. 对自动切分的影响

`segment_into_trips` 建议：

```text
同一城市：
  景区变化 → 新子行程
  景区相同 → 继续按时间间隔
  景区未知 → 回退城市+时间
```

宜昌样本按此规则，理论上可自动切成：

- 三峡大坝（5 张）
- 听风谷（22 张，独立途经点）
- 三峡人家（约 98 张）
- 清江画廊（约 60 张）
- 宜昌城区/其他（约 20 张，含磨基山对岸晚餐 3 张）

听风谷与三峡人家时间不重叠（10:22–10:30 vs 11:45–15:09），空间相距约 6–7km，已确认独立成点。

---

## 7. 建议实施顺序

1. **后端**：AOI + 父级链候选，写入 `area_name/area_source`；
2. **POI 审核**：显示候选，支持批量确认/新建/别名；
3. **切分**：加入景区边界；
4. **拆分 UI**：按景区自动分组 + 手动调整；
5. **LLM**：等真实歧义样本后再做。

---

## 8. 已确认的决策（2026-11-16）

- 接受“AOI 优先、父级链兜底、人工确认”的候选策略；
- 听风谷独立成点，不自动并入三峡人家；
- 磨基山 3 张保留高德 API 返回（磨基山森林公园），不做本次人工覆盖，也不建全局别名；后续由用户在前端实测时决定是否手动调整；
- v1.0 **不增加“活动”标签**，先只做地理景区字段：
  - `area_name`
  - `area_source`
  - `area_confidence`（可选）
- 如果以后确实需要区分“景区游览/晚餐/途经”，单独增加 `activity_type`，不要混入景区字段，也不要用一次活动修改全局地理规则；
- 人工修正默认“仅本次”，只有明确勾选才写入别名；
- LLM 只做后续歧义辅助，不进入 v1.0。
